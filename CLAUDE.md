## How the site works
- Django + django-distill, published as plain HTML on Render (free static site, see render.yaml). Pushing to GitHub redeploys automatically.
- All content is in content/ (Markdown pages, JSON data, history.html); photos in static/img/; styles in static/css/site.css. See README.md for the full map.
- Templates must stay readable by both Django and Jinja2 (build_preview.py): use only extends, block, include, for, if, {{ value }} and |safe. No {% static %} or {% url %}; use {{ static }} and plain paths. Don't name JSON keys "items", "keys" or "values".
- Before pushing: run `python manage.py distill-local public --force --collectstatic` and check pages at phone width (390px) and desktop.

## Design rules
- Palette from the church: brick #8b3a2b, ink #1b2233, glass blue #1e4f8f, gilt #b8892b (decoration and focus only, never text), plaster #f5f6f3. Fonts: Marcellus (headings), Public Sans (body).
- Pointed-arch motif (like the church windows) is used only for the homepage photo and the logo. Keep it rare.
- Calendar and Give must stay easy to see on every page, including phones. Keep WCAG AA contrast, visible focus, 44px tap targets, alt text on every meaningful photo.

## Routine updates
- Monthly calendar: add the PDF to static/calendar/ and a line to content/calendar.json ("YYYY-MM": "/static/calendar/file.pdf"). The site names this month and next month automatically.
- Livestream goes public: set "livestream_public": true in content/site.json.
- Service times: content/schedule.json. Ministries: content/ministries.json.
- Events come from the monthly calendar: when Fr. Arkady sends a new month's calendar PDF, read it and add each feast, special service and parish event (not the regular weekly services) to content/events.json (date YYYY-MM-DD, optional end_date, title, time, text, optional photo). Copy times exactly from the calendar; never invent them. Events move from "Coming up" to "Past events" by themselves after their date; the homepage shows the next four. If the calendar shows a little picture next to an event (clip art or an icon), cut it out of the PDF, save it in static/img/ as event-<name>.jpg on a white background, and set image, image_alt and "image_small": true on that event.
- After an event (Parish life stories): when Fr. Arkady sends a few words and photos from a past event, write a short story in content/parish-life/YYYY-MM-DD-short-name.md (header: title, date, summary of one or two sentences, image = main photo in static/img/ without .jpg, image_alt, and "featured: yes" only if he wants it on the homepage). Body: two to four short paragraphs from his own words, never invented details (no names, numbers or quotes he didn't give), then any extra photos as Markdown images with alt text (/static/img/story-<name>-1.jpg, resized to about 1600px wide). Add "story": "<file name without .md>" to the matching event in content/events.json so the event links to it. Only use photos he has permission to use; children only seen from behind unless parents agreed.
- Homepage "From parish life" spot: shows the newest story with "featured: yes" for 6 weeks after its date (FEATURE_DAYS in parish/routes.py), in place of the "More than Sunday morning" photos; then those photos come back by themselves (static/js/feature.js). Only one story is ever on the homepage, so feature only the big ones (Pascha, patronal feast, a bishop's visit, baptisms, the St. Nicholas visit). The three newest featured stories also stay on the Events page under "Highlights from parish life" (top of Past events) for good. Every story, featured or not, is listed at /parish-life/ by year.
- Past events: the Events page keeps the last 90 days of past events open; older ones fold into "Earlier events in <year>". Nothing needs deleting.
- Service texts (/worship/service-texts/): when Fr. Arkady sends a service book, save the PDF in static/texts/ with a plain name (great-vespers.pdf, divine-liturgy.pdf, moleben-st-elizabeth.pdf, panikhida.pdf, baptism.pdf) and set "file": "/static/texts/<name>.pdf" on that entry in content/service_texts.json. Empty file shows "Coming soon". A new kind of service gets a new entry (title, one-line text, file) in the right group. Keep PDFs small (compress if over ~10 MB). Before posting, ask whose translation it is and whether the parish may post it publicly (many English service books are copyrighted).
- Contact message form (/contact/#message, static/js/message.js): sends through Web3Forms (free) to the email that owns the access key. The key goes in content/site.json "contact_form_key" (it is meant to be public, so it's fine in the page). With no key, or if sending fails, the form opens the visitor's own email app addressed to office@. The hidden "botcheck" field catches spam robots.
- Bulletin: put the PDF in static/bulletin/ and set url and label (e.g. "Sunday, November 22") in content/bulletin.json. Empty url shows "Coming soon".
